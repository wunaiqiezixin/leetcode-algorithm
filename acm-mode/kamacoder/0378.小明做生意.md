# [Xiaoming Business](https://kamacoder.com/problempage.php?pid=1458)

---

> 数据范围：`1 ≤ k ≤ 1000`，`0 ≤ m ≤ 1000`、`0 ≤ cost[i], profit[i] ≤ 1000`，商品数量 `1 ≤ n ≤ 200`。
>
> 题型：有限次数购买 + 动态增长预算。本文给出两种等价且均已验证的解法：**解法一 排序 + 0/1 背包（DP）**，**解法二 贪心 + 优先队列**。

## 题目分析

小明有初始现金 `m`，要在 `k` 天内（每天最多进 1 次货、买 1 件，**每种商品只有 1 件库存**）做生意。买入商品 `i` 需要当场付 `cost[i]`（"不能赊账" → 当前现金必须 ≥ `cost[i]`），买完卖出净赚 `profit[i]`，于是现金等价于 **现金 += profit[i]**（先付 cost 再收回 cost+profit）。

目标：在至多 `k` 次购买内，最大化总利润（= 最终现金 − 初始现金）。

**两个本质观察**：
1. 任意一次购买（只要买得起）都会让现金**净增加** `profit[i] ≥ 0`，所以本金只会越买越多，能买得起的商品也越来越多。
2. 既然买任何买得起的商品都不亏，且带来的是「现金增量」，那最大化利润的瓶颈只在于「每天挑哪一件」，而非「要不要买」。

---

## 解法一：排序 + 0/1 背包（动态规划）

### 为什么用这个思路（核心：必须按成本升序）

有人会想贪心：每次挑利润最大的买。但**利润大的商品往往也贵**，钱不够就买不了。关键是 —— **便宜的商品先买能先把现金垫高，从而买得起后面更贵、利润更高的商品**。所以这是「选一个子集、且子集内部要满足赊账约束」的最优化问题。

但有一个事实：对于任意一个可行的购买集合，把它**按成本升序**购买是最宽松的（每一步现金尽可能高，最容易满足「现金 ≥ 下一笔成本」）。也就是说「某个集合能否被买到」等价于「按成本升序买它能否全程够钱」。基于这点，就能用 DP 枚举「选哪些商品」而不必枚举顺序：

- 状态：`dp[j]` = **恰好买 j 件商品**后能达到的最大现金；`-1` 表示不可达。
- 初始：`dp[0] = m`（一件不买，手里就是初始现金），其余 `-1`。
- 转移：把所有商品**先按 `cost` 升序排序**，再对每件商品做 0/1 背包（倒序 `j` 更新，保证每件最多买一次）：
  ```
  若 dp[j-1] >= 0 且 dp[j-1] >= cost[i]：
      dp[j] = max(dp[j], dp[j-1] + profit[i])
  ```
  含义：若之前买的 `j-1` 件（都是更便宜的）能凑出钱 `dp[j-1]`，且这笔钱够买当前商品 `i`，就把 `i` 当作第 `j` 件买，现金增加 `profit[i]`。
- 答案：`max(dp) - m`（利润 = 最终现金 − 初始现金）。因为 `profit ≥ 0`，买得越多现金不降，直接取 `max` 即可。

### 为什么必须排序（最容易翻车的一点）

如果不排序，DP 按输入顺序逐个考虑商品：当一件「贵但利润高」的商品排在「便宜商品」前面时，DP 在处理它时还不知道后面便宜商品能带来的现金，于是 `dp[j-1]`（来自更前面、可能也很贵的商品）不够钱，导致这件高利润商品永远进不了集合。排序后，便宜商品先被处理、`dp` 先被垫高，贵的商品自然能被「接」上去。

举例：`k=7, m=18, cost=[19,1,18], profit=[3,15,3]`。
- 不排序：先遇到 `cost=19`（现金 18 买不起），再遇到 `cost=1` 后现金涨到 33，但此时已没法回头把 `cost=19` 接成第 2、3 件，最终最多赚 18。
- 按 `cost` 升序 `[1→15, 18→3, 19→3]`：买 `(1,15)` 现金 33 → 买 `(18,3)` 现金 36 → 买 `(19,3)` 现金 39，总利润 **21**。

### 完整代码（C++）

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int k;                               // 最多购买次数（天数）
    if (!(cin >> k)) return 0;
    int m;                               // 初始现金
    cin >> m;

    // 题目格式：第三行 cost，第四行 profit，两行元素个数相同。
    // 用 >> 逐一读取剩余整数，前半段为成本、后半段为利润。
    vector<ll> all;
    ll x;
    while (cin >> x) all.push_back(x);
    int n = (int)all.size() / 2;         // 两行等长 → 半数为成本
    vector<pair<int, int>> items;
    for (int i = 0; i < n; ++i)
        items.emplace_back((int)all[i], (int)all[i + n]);  // (cost, profit)

    // 灵魂一步：按成本升序，保证“先买便宜的攒钱”
    sort(items.begin(), items.end());    // pair 默认按 first（cost）升序

    // dp[j] = 恰好买 j 件后的最大现金；-1 表示不可达
    vector<ll> dp(k + 1, -1);
    dp[0] = m;

    // 0/1 背包：倒序遍历 j，每件商品最多买一次
    for (auto [c, p] : items) {
        for (int j = k; j >= 1; --j) {
            if (dp[j - 1] >= 0 && dp[j - 1] >= c) {  // 之前 j-1 件能攒出 >= cost 的钱
                dp[j] = max(dp[j], dp[j - 1] + p);
            }
        }
    }

    ll ans = 0;
    for (ll v : dp) if (v > 0) ans = max(ans, v - m);  // 利润 = 最终现金 - 初始
    cout << ans << '\n';
    return 0;
}
```

### 示例走查（与题目一致）

输入：
```
3
2
2 5 7
2 5 7
```
- `cost=[2,5,7], profit=[2,5,7]`，按 cost 升序仍是 `[2,5,7]`。
- `dp[0]=2`。
- 商品 `(2,2)`：`dp[1] = 2+2 = 4`。
- 商品 `(5, 5)`：`dp[2]` 需 `dp[1]=4 ≥ 5`？否，无法扩展；`dp[1]` 保持 4。
- 商品 `(7,7)`：同理买不起。
- `max(dp)=4`，利润 = `4 − 2 = 2`。 输出 `2`。

## 解法二：贪心 + 优先队列

### 思路分析

这道题的核心在于：我们在有限的 `k` 天内，每天只能买一件商品，并且希望总利润最大。由于每次交易后，我们的本金都会增加（增加的金额即为该商品的利润），所以只要是我们当前买得起的商品，买了就一定能增加本金。本金越多，后续就能买得起成本更高的商品。

要让利润最大化，我们可以采用贪心策略：**优先考虑当前能买得起的、利润最大的商品**。

为了快速找到当前本金能买得起的商品，我们可以先将所有商品按照成本价（`cost`）升序排序。维护一个大顶堆（优先队列），用于存储所有「当前本金可以买得起」的商品的利润。在每一天（最多 `k` 天）：

1. 遍历排序好的商品列表，将所有 `cost ≤ 当前本金` 的商品利润放入大顶堆中；
2. 如果大顶堆为空，说明剩下的商品都买不起了，直接结束；
3. 如果大顶堆不为空，弹出堆顶元素（即当前能买到的最大利润），将其加入总利润和当前本金中。

> **为什么贪心选「最大利润」永远不亏？** 买任何买得起的商品，现金净增量都精确地等于它的 `profit`，与 `cost` 无关。所以利润越大的商品，给后续攒下的本金越多、未来能解锁的商品也越多——它在「当前收益」和「未来潜力」两个维度上都严格占优。因此每天从买得起的集合里取最大利润，就是全局最优。

### 复杂度分析

- 时间复杂度：**O(N log N + K log N)**；其中 N 为商品数量，K 为天数。排序需要 `O(N log N)`；在最多 K 次循环中，每个商品最多入堆/出堆一次（堆操作 `O(N log N)`），每次弹出最大值 `O(K log N)`。
- 空间复杂度：**O(N)**；需要数组存储商品信息，并用优先队列维护利润，最大占用 `O(N)` 空间。

### 代码实现（C++）

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>
#include <sstream>
#include <string>
using namespace std;

int main() {
    // 优化输入输出
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    string line;
    if (!getline(cin, line)) return 0;      // 第一行：天数 k
    int k = stoi(line);

    getline(cin, line);                     // 第二行：初始本金 m
    int m = stoi(line);

    getline(cin, line);                     // 第三行：成本 cost
    stringstream ss1(line);
    vector<int> cost;
    int temp;
    while (ss1 >> temp) cost.push_back(temp);

    getline(cin, line);                     // 第四行：利润 profit
    stringstream ss2(line);
    vector<int> profit;
    while (ss2 >> temp) profit.push_back(temp);

    int n = cost.size();
    vector<pair<int, int>> items(n);
    for (int i = 0; i < n; ++i) {
        items[i] = {cost[i], profit[i]};
    }
    // 按成本价从小到大排序
    sort(items.begin(), items.end());

    // 大顶堆，存储利润
    priority_queue<int> pq;
    int current_money = m;
    int total_profit = 0;
    int idx = 0;                            // 已加入堆的商品下标（cost 升序，可双指针）

    for (int i = 0; i < k; ++i) {
        // 将所有当前买得起的商品利润加入大顶堆
        while (idx < n && items[idx].first <= current_money) {
            pq.push(items[idx].second);
            idx++;
        }
        // 如果买不起任何新商品，直接结束
        if (pq.empty()) {
            break;
        }
        // 取出能获得的最大利润
        int max_profit = pq.top();
        pq.pop();
        current_money += max_profit;        // 本金增加（=利润，等价于 -cost+成本+profit）
        total_profit += max_profit;
    }

    cout << total_profit << "\n";
    return 0;
}
```

## 两种解法的对比

| 维度 | 解法一（DP） | 解法二（贪心 + 堆） |
|------|-------------|---------------------|
| 思想 | 枚举「选哪些商品」（0/1 背包，按件数状态） | 每天从买得起的集合取最大利润 |
| 排序 | 必须按 `cost` 升序 | 必须按 `cost` 升序 |
| 核心结构 | `dp[j]` + 倒序更新 | 大顶堆 + 双指针 `idx` |
| 复杂度 | `O(N·K)`（`N≤200, K≤1000` 很宽松） | `O(N log N + K log N)` |
| 直观性 | 偏「正确性证明」向 | 偏「模拟决策」向，更易想 |


## 关键细节 / 易错点

- × **漏掉「按成本升序排序」**（两种解法都依赖它）→ 高利润贵商品无法被买，答案偏小。
- × DP 正序遍历 `j`（从 1 到 k）→ 同一商品被重复购买。
- × 把「利润」当「卖价」：实际现金变化是 `+= profit`，不是 `-=cost` 之后忘了加回。
- × 忘记「最多 k 天」约束，无脑买光 n 件 → 超出天数限制（解法二用 `for(i<k)` 自然截断；解法一 dp 维度只到 k）。
- 数据类型：`m ≤ 1000`、每件利润 ≤ 1000、最多 200 件，`int` 够用（上界约 2×10⁵），但养成用 `long long` 的习惯更稳（解法一用了 `long long`，解法二用 `int` 也正确）。

## 一句话总结

把商品按成本升序排好：要么跑「按购买件数」的 0/1 背包（`max(dp) − m`），要么每天从买得起的集合里用大顶堆取最大利润——**排序是灵魂，贪心取最大利润永远不亏，DP 与贪心结果完全等价**。
