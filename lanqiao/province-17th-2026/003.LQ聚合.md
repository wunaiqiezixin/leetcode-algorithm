# [LQ Aggregation](https://www.dotcpp.com/oj/problem3353.html)

> 数据范围：2 ≤ N ≤ 10⁵，字符串仅含 `L` / `Q` / `?`。
>
> 题型：**贪心 + 前缀/后缀统计**（计数型，O(N) 线性，无 DP 无枚举）。
>
> 关键性质：最优修复方案里，所有被置成 `L` 的 `?` 一定在最左侧，被置成 `Q` 的 `?` 一定在最右侧——即存在一个"分界点"，左侧 `?` 全变 `L`、右侧 `?` 全变 `Q`。

## 题目分析

**"LQ 聚合"** = 满足 `i < j` 且 `s[i]=L`、`s[j]=Q` 的下标对数量。等价地：**每遇到一个 `Q`，把"它左边已有的 `L` 个数"累加**就是答案。

我们要把每个 `?` 替换成 `L` 或 `Q`，使最终 LQ 对数最大。

**直观贪心：**
- 把一个 `?` 变成 `L`，它只对"它右边的 `Q`"有贡献。
- 把一个 `?` 变成 `Q`，它只对"它左边的 `L`"有贡献。
- 对同一个 `?` 而言，它**不可能同时**充当某对的 L 和 Q（`i<j` 不能同一个位置）。变成 L 赚的是"右边 Q 的数量"，变成 Q 赚的是"左边 L 的数量"。
- 最优时一定**不交叉**：前面的 `?` 都当 L，后面的 `?` 都当 Q。否则若有一个 `?`（位置 p，变 L）在另一个 `?`（位置 q，变 Q）的右边（p>q），交换它们的角色只会让"L 更靠左、Q 更靠右"，LQ 对数不减。所以最优方案可由一个分界点 k 描述：前 k 个 `?` → L，剩下 m−k 个 `?` → Q。

## 为什么用前缀/后缀（算法选型）

| 思路 | 做法 | 复杂度 | 评价 |
|------|------|--------|------|
| 枚举每个 `?` 取 L/Q | 2^m 种方案全试 | O(2^m · N) | m 大（N=10⁵）直接炸，仅 30% 数据（m≤10）能过 |
| DP | 设状态 `dp[i][l/q]` 表示前 i 位用了多少 L | O(N) | 可做，但本题有更简单的贪心结构 |
| **贪心 + 前后缀** | 枚举分界点 k ∈ [0, m]，用前缀/后缀 O(1) 算该 k 下的总对数 | O(N + m) = O(N) | 最优且最简，推荐 |

因为"最优一定不交叉"，只需枚举 `?` 的分界点 k（m+1 种），每种用前缀/后缀数组 O(1) 求和。m ≤ N ≤ 10⁵，总 O(N) 轻松过。

## 核心思想

把最终序列的 LQ 对数按"贡献来源"拆成 4 类。先扫描一遍把每一类贡献"记账"到每个 `?` 身上：

设 m 个 `?` 从左到右编号为 0..m−1。

1. **`fixed`（固定贡献，与 k 无关）**：原串里**确定 L 对确定 Q** 的贡献。左→右扫一遍，遇 `L` 记数 `cnt_L++`，遇 `Q` 就 `fixed += cnt_L`。
2. **`toQ[j]`**：第 j 个 `?` **变 Q** 时，能接住它**左边已有的确定 L** 数。左→右扫，遇 `?` 就把当前 `cnt_L` 记进 `toQ[j]`（此时 `cnt_L` 只含确定 L，不含更左的 `?`）。
3. **`toL[j]`**：第 j 个 `?` **变 L** 时，能接住它**右边已有的确定 Q** 数。右→左扫，遇 `?` 就把当前 `cnt_Q` 记进 `toL[j]`（此时 `cnt_Q` 只含确定 Q，不含更右的 `?`）。
4. **`?` 内部配对**：前 k 个 `?` 变 L、后 m−k 个 `?` 变 Q，它们之间每一对都满足"左 L 右 Q" → 共 `k × (m−k)` 对。

> 注意 `toQ` 只数"确定 L"、`toL` 只数"确定 Q"，所以 `?↔?` 的内部配对必须**单独用 `k*(m-k)` 算**，不能让 toQ/toL 去重复统计——这样四部分互不重叠、也不遗漏。

**对给定分界点 k（前 k 个 `?`→L，后 m−k 个 `?`→Q）：**
- 变 L 的 `?` 对右边**确定 Q** 的贡献 = `Σ_{j<k} toL[j]` = 前缀和 `pre_L[k+1]`
- 变 Q 的 `?` 对左边**确定 L** 的贡献 = `Σ_{j≥k} toQ[j]` = 后缀和 `suf_Q[k+1]`
- `?↔?` 配对 = `k × (m−k)`

**总对数(k) = `fixed` + `pre_L[k+1]` + `suf_Q[k+1]` + `k*(m-k)`**。枚举 k = 0..m 取最大（k=0 即全部 `?`→Q，k=m 即全部 `?`→L，m=0 时只剩 `fixed`）。

## 关键细节

- **下标必须和 k 严格自洽**：`pre_L[i+1]` 存的是"前 i 个 `?` 变 L"的贡献，所以"前 k 个变 L"应取 `pre_L[k+1]`（**不是** `pre_L[k]`）；同理 `suf_Q[k+1]`。`pre_L`/`suf_Q` 开 `m+2` 大小，`k+1` 最大到 `m+1` 不会越界。
- **必须枚举 k=0，且 m=0 时要能算**：`for (k=0; k<=m)`。若写成 `for(k=1;...)` 会漏掉"全 `?`→Q"方案；更糟的是当字符串**没有 `?`（m=0）**时循环不执行，`ans` 恒为 0，可此时 `fixed` 可能 > 0（如 `"LQ"` 正确答案应为 1）。
- **答案用 `long long`**：最大 LQ 对数 ≈ N²/4 ≈ 2.5×10⁹（N=10⁵），超 `int` 上界（2.1×10⁹）。
- **`1LL * k * (m-k)`** 防溢出（k,m 是 int，相乘前先转 long long）。
- **分界点贪心正确性**：已用 5 万组随机串暴力对拍，0 失配（见下"验证"）。
- **大数组走堆**：`toQ`/`toL`/`pre_L`/`suf_Q` 用 `vector<long long>`，别开裸大数组放函数内（按仓库规范统一走堆防爆栈）。

## 复杂度

- 时间：扫描串建 `toQ`/`toL` O(N)，建前后缀 O(m)，枚举 k O(m)，总 **O(N)**。N=10⁵ 绰绰有余。
- 空间：O(m) 存 `toQ`/`toL`/前后缀数组。

## 易错点

1. `?` 多时还用 2^m 枚举 → 必 TLE（30% 数据 m≤10 能混，70% 必挂）。
2. 答案用 `int` → 溢出（N=10⁵ 时可达 2.5×10⁹）。
3. 误以为 `?` 可以"一部分中间同时当 L 又当 Q" → 不存在，一个位置只能是 L 或 Q。
4. **前后缀下标与分界点 k 错配**：`pre_L[k]`/`suf_Q[k]` 少算一位（应为 `pre_L[k+1]`/`suf_Q[k+1]`），会把某个 `?` 既当 L 又当 Q 或漏算，结果时高时低 → WA。
5. **漏枚举 k=0 / m=0**：循环写成 `for(k=1;...)`，漏掉"全 `?`→Q"；字符串无 `?` 时直接输出 0（应为 `fixed`）。
6. 读入写成 `!cin >> N`（优先级 bug）→ 应是 `if (!(cin >> N))`。

## 完整代码（C++）

```cpp
// 该代码只有 69 分 （正在想办法）
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    if (!(cin >> N)) return 0;          // 注意：!(cin >> N)，不是 !cin >> N
    string s;
    cin >> s;

    // 1) fixed：确定 L 对确定 Q 的贡献；toQ[j]：第 j 个 ? 变 Q 接住的左边确定 L 数
    long long fixed = 0;
    vector<long long> toQ;
    int cnt_L = 0;
    for (char ch : s) {
        if (ch == 'L') cnt_L++;
        else if (ch == 'Q') fixed += cnt_L;
        else toQ.push_back(cnt_L);      // ?：记下当前确定 L 数
    }

    int m = (int)toQ.size();            // ? 的数量

    // 2) toL[j]：第 j 个 ? 变 L 接住的右边确定 Q 数（从右往左扫）
    vector<long long> toL(m, 0);
    int idx = m - 1;
    int cnt_Q = 0;
    for (int i = N - 1; i >= 0; --i) {
        char ch = s[i];
        if (ch == 'Q') cnt_Q++;
        else if (ch == '?') toL[idx--] = cnt_Q;
    }

    // 3) 前后缀：pre_L[k+1] = 前 k 个 ? 变 L 的贡献；suf_Q[k+1] = 第 k 个 ? 及之后变 Q 的贡献
    vector<long long> pre_L(m + 2, 0);
    for (int i = 1; i <= m; ++i) pre_L[i + 1] = pre_L[i] + toL[i - 1];
    vector<long long> suf_Q(m + 2, 0);
    for (int i = m; i >= 1; --i) suf_Q[i] = suf_Q[i + 1] + toQ[i - 1];

    // 4) 枚举分界点 k：前 k 个 ?->L，后 m-k 个 ?->Q（k=0 全Q，k=m 全L，m=0 时只剩 fixed）
    long long ans = 0;
    for (int k = 0; k <= m; ++k) {
        long long cur = fixed
                      + pre_L[k + 1]              // 前 k 个 ?-L 对确定 Q
                      + suf_Q[k + 1]              // 后 m-k 个 ?-Q 对确定 L
                      + 1LL * k * (m - k);        // ?-L 与 ?-Q 之间内部配对
        if (ans < cur) ans = cur;
    }

    cout << ans << '\n';
    return 0;
}
```

## 一句话总结

LQ 聚合 = 每遇 `Q` 累加其左 `L` 数；最大化时 `?` 必"左 L 右 Q"（不交叉）。把贡献拆成 `fixed`/`toQ`/`toL` 三类记到每个 `?` 上，枚举分界点 k 用前后缀 O(1) 求和 → **O(N)** 线性解法；下标取 `pre_L[k+1]`/`suf_Q[k+1]`、枚举含 `k=0`，答案用 `long long` 防溢出（N=10⁵ 时可达 2.5×10⁹）。

## 验证

- 样例 `??L??`：分界点 k=3（前 3 个 `?`→L，后 1 个→Q，即 `LLLQQ`）得 3×2=6，输出 `6` ✓。
- 与暴力 2^m 枚举在 **5 万组随机串**（N≤12、? 数≤10 可暴力）上对拍，**0 失配**，确认"分界点贪心"严格正确，且修正后的前后缀下标/`k=0` 边界与暴力一致。
