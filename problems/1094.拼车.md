# [Car Pooling](https://leetcode.cn/problems/car-pooling/description/)
> 数据范围：`1 <= trips.length <= 1000`，每条 `trips[i] = [numpassengers, from, to]`，`1 <= numpassengers <= 100`，`0 <= from < to <= 1000`，`1 <= capacity <= 10^5`
>
> 题型：**差分数组（Difference Array）**——本质是「区间加法 + 前缀和 + 峰值查询」；和 [Corporate Flight Bookings](./1109.航班预订统计.md) 同宗，但注意**下车点 `to` 不占座位（左闭右开区间）**。`解法二` 另给**事件扫描线**写法（坐标范围大、差分数组开不下时的通用形态，与差分同源不同表示）。

## 题目分析

一辆车初始有 `capacity` 个空座位，只能单向行驶。每次行程 `trips[i] = [num, from, to]` 表示有 `num` 名乘客在位置 `from` 上车、在位置 `to` **下车**。

问：能否在所有行程中接送所有乘客而不超载？即**任意时刻车上人数都不超过 capacity**。

把"位置"看成公里刻度，乘客在 `[from, to)` 这段区间内占据座位（`from` 上车、`to` 下车，到达 `to` 时人已离开，**`to` 这一点不占座**）。于是问题变成：在 `0..1000` 这条轴上，若干区间 `[from, to)` 各加 `num`，求**任意位置被覆盖的总人数峰值**是否 ≤ `capacity`。

## 为什么用差分数组（算法选型对比）

| 做法 | 思路 | 复杂度 | 评价 |
|---|---|---|---|
| 排序 + 优先队列/map 扫描线 | 按 `from` 排序，到每个上车点先放掉已到 `to` 的人，再加新人 | O(m log m) | 也正确，但代码更啰嗦 |
| 朴素枚举每个位置 | 对每个 `x` 累加所有覆盖它的区间 | O(m · L)，L≤1001 | 可过（m≤1000 很小），但没用到结构 |
| 差分数组 | 端点 ±num，前缀和还原，边走边判峰值 | O(m + L) | 最简洁，L=1001 常数极小 |

- `L = 1000` 上限很小，差分数组建一个长度 1001 的数组即可，O(m+L) 稳过，且代码最短。
- 本质就是 [Corporate Flight Bookings](./1109.航班预订统计.md) 的孪生题——只不过那题是**闭区间**（减在 `last+1`），本题是**左闭右开区间**（减在 `to`，因为 `to` 不占座）。

## 核心思想

构造差分数组 `diff`（长度 1001，`to` 最大为 1000，下标取得到）：

- `diff[from] += num`：在 `from` 上车，`from` 起每段路多 `num` 人。
- `diff[to]   -= num`：**在 `to` 下车**，`to` 起每段路少 `num` 人（`to` 这一点本身已不在车上）。

做一次前缀和（维护滚动变量 `cur`），`cur` 就是当前路段车上的实时人数；**只要出现 `cur > capacity` 就直接返回 `false`**，全程都不超则返回 `true`。

> 关键：差分 + 前缀和得到的 `cur[x]` 表示**位置 `x` 到 `x+1` 这段路上**车上的人数，正好对应"乘客在 `[from, to)` 占座"的语义。

## 关键细节

1. **`to` 是下车点、不占座 → 左闭右开 `[from, to)`**：减操作必须落在 `to`（不是 `to+1`）。若误写成 `diff[to+1] -= num`，会把 `to` 这一小段多算进去（把已经下车的人又算成还在车上），导致误判超载 / 漏判超载。这是本题和航班预订（闭区间 `last+1`）的根本区别。
2. **0-indexed**：地点从 `0` 起，`from`、`to` 直接当下标，数组长度 1001（下标 `0..1000`）足够，无需额外偏移。
3. **只需判峰值**：不返回每站人数，前缀和过程中边走边比 `capacity` 即可，第一次超就 `return false`。

## 复杂度

- 时间：`O(m + L)`，`m` 条行程 + 扫描 1001 个位置。
- 空间：`O(L)`，`diff` 长度 1001。

## 易错点

1. **区间开闭搞反**：本题 `to` 不占座，减在 `to`；航班预订是闭区间，减在 `last+1`。两题差分数组端点位置不同，**不要套错**。
2. **`to` 越界**：`to` 最大 1000，若写成 `diff[to+1] -= num` 需数组长度 1002；按本题语义应减在 `to`，长度 1001 刚好。
3. 行程内 `num` 用 `int` 足够：峰值最坏 `1000 行程 × 100 人 = 1e5`，远小于 `capacity` 上限 `1e5` 与 `int` 范围，无需 `long long`。

## 完整代码（C++）

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        // 地点 0-indexed，最大 to = 1000；to 是下车点不占座（左闭右开 [from, to)）
        vector<int> diff(1001, 0);
        for (const auto& t : trips) {
            int num  = t[0];
            int from = t[1];
            int to   = t[2];
            diff[from] += num;   // from 上车
            diff[to]   -= num;   // to 下车（to 这一段已不在车上）
        }
        int cur = 0;             // 前缀和 = 当前路段车上人数
        for (int x = 0; x <= 1000; ++x) {
            cur += diff[x];
            if (cur > capacity) return false;   // 任意时刻超载即失败
        }
        return true;
    }
};
```

## 解法二：排序 + 优先队列 / map 扫描线（另一种思路）

差分数组是"用数组下标直接定位端点"的特例（因为 `to ≤ 1000` 范围极小，可以直接当下标）。当**坐标范围很大、或区间端点稀疏**时，更通用的做法是**事件扫描线**：把所有行程按上车点 `from` 排序，用一个结构维护"当前在车上的乘客"，每到一个上车点先放掉已经下车的、再加新上车的。

### 核心思想

- 把行程按 `from` 升序排序，依次处理。
- 维护当前车上人数 `on` 和一个"待下车"集合：
  - **优先队列版**：小顶堆 `(-to, num)`（按下车点 `to` 最小优先），每次先 `pop` 所有 `to ≤ 当前 from` 的乘客（他们已下车，`on` 减去对应人数），再让当前行程的 `num` 上车。
  - **map 版**：`unordered_map<int,int>` 记录"每个下车点还有多少人没下"，到每个 `from` 先把 `key ≤ from` 的桶减掉，再把当前 `num` 累加到 `to` 这个桶。
- 每个上车点检查 `on > capacity` → 超载返回 `false`；全程不超则返回 `true`。

> 为什么"先下后上"不会错：题目保证 `from < to`，且两段路之间才算超载。处理 `from` 这一刻，所有 `to ≤ from` 的乘客**在到达 `from` 之前就已经下车了**，所以必须先扣掉再上新人，才能反映 `from→to` 这段的真实人数。

### 完整代码（C++）

**优先队列版（推荐：O(m log m)，堆操作紧凑）**

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        // 按上车点 from 排序
        sort(trips.begin(), trips.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });

        // 小顶堆：pair<to, num>，按 to 最小优先（先下车的先 pop）
        using P = pair<int, int>;
        priority_queue<P, vector<P>, greater<P>> pq;
        int on = 0;                                  // 当前车上人数

        for (const auto& t : trips) {
            int num  = t[0];
            int from = t[1];
            int to   = t[2];
            // 1) 先放掉所有 to <= from 的乘客（已到达下车点）
            while (!pq.empty() && pq.top().first <= from) {
                on -= pq.top().second;
                pq.pop();
            }
            // 2) 当前乘客上车
            on += num;
            if (on > capacity) return false;         // 超载
            pq.emplace(to, num);                     // 记录待下车
        }
        return true;
    }
};
```

**map 版（按下车点计数，思路更直白）**

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        sort(trips.begin(), trips.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });

        unordered_map<int, int> drops;               // 下车点 to -> 待下人数
        int on = 0;

        for (const auto& t : trips) {
            int num  = t[0];
            int from = t[1];
            int to   = t[2];
            // 1) 先让所有 to <= from 的乘客下车
            for (auto it = drops.begin(); it != drops.end(); ) {
                if (it->first <= from) {
                    on -= it->second;
                    it = drops.erase(it);
                } else {
                    ++it;
                }
            }
            // 2) 当前乘客上车
            on += num;
            if (on > capacity) return false;
            drops[to] += num;                        // 记录待下车
        }
        return true;
    }
};
```

### 复杂度

- 优先队列版：时间 `O(m log m)`（排序 + 每个行程一次堆插入/弹出），空间 `O(m)`（堆最坏存全部行程）。
- map 版：时间 `O(m log m)`（排序 + 桶增删，map 操作 log），空间 `O(m)`。
- 两者都比差分数组 `O(m + L)` 略慢（多一个 log），但**不依赖坐标范围**——当 `to` 可以很大（如 1e9）时，差分数组开不下，扫描线就是唯一选择。

### 和差分数组的关系

- 差分数组与事件扫描线是**同一思想的两种表示**：差分数组是坐标范围小、可哈希成数组下标时，用 `O(L)` 数组直接累加端点（等价"排序事件后 sweep"，但省去排序）；事件扫描线是坐标巨大/稀疏、开不下数组时，必须显式排序端点 + 维护当前值。
- **严格术语里"扫描线（sweep line）"特指后者的"事件排序 + sweep"形态**，差分数组是其"可索引特例"。所以本题**主解是差分数组**，真正叫扫描线的是这里的解法二；而 [Circle Points](../acm-mode/kamacoder/0395.圈点.md) 全篇用的就是规范意义上的事件扫描线（求区间最大重叠）。
- 本题 `to ≤ 1000` 极小，差分数组最简洁；但**理解扫描线**能让你在"区间端点稀疏 / 坐标巨大"的同类题直接套用，不必拘泥于数组。

## 一句话总结

拼车 = 差分数组的**左闭右开**版本：上车点 `+num`、下车点 `to` `-num`（注意 `to` 不占座，不是 `to+1`），前缀和边走边判峰值是否超 `capacity`；和航班预订统计同宗，别把闭区间的 `last+1` 套过来。若坐标范围大、端点稀疏，改用**排序 + 优先队列/map 扫描线**（先下后上、边扫边判峰值），逻辑等价且不依赖数组长度。
