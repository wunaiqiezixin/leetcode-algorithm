# [Implement Trie (Prefix Tree)](https://leetcode.cn/problems/implement-trie-prefix-tree/)

---

## 题目描述

**Trie**（发音类似 "try"）或者说**前缀树**是一种树形数据结构，用于高效地存储和检索字符串数据集中的键。这一数据结构有相当多的应用情景，例如自动补完和拼写检查。

请你实现 `Trie` 类：

- `Trie()` 初始化前缀树对象。
- `void insert(String word)` 向前缀树中插入字符串 `word`。
- `boolean search(String word)` 如果字符串 `word` 在前缀树中，返回 `true`（即，在检索之前已经插入）；否则，返回 `false`。
- `boolean startsWith(String prefix)` 如果之前已经插入的字符串 `word` 的前缀之一为 `prefix`，返回 `true`；否则，返回 `false`。

### 示例

```
输入
["Trie", "insert", "search", "search", "startsWith", "insert", "search"]
[[], ["apple"], ["apple"], ["app"], ["app"], ["app"], ["app"]]

输出
[null, null, true, false, true, null, true]

解释
Trie trie = new Trie();
trie.insert("apple");
trie.search("apple");   // 返回 True
trie.search("app");     // 返回 False
trie.startsWith("app"); // 返回 True
trie.insert("app");
trie.search("app");     // 返回 True
```

### 数据范围

- `1 <= word.length, prefix.length <= 2000`
- `word` 和 `prefix` 仅由小写英文字母组成
- `insert`、`search` 和 `startsWith` 调用次数**总计**不超过 `3 * 10^4` 次

## 什么是 Trie（前缀树）

Trie 是一棵多叉树，专门用于处理字符串匹配。它的核心思想是：**利用字符串的公共前缀来减少查询时间，最大限度地减少无谓的字符串比较**。

### Trie 的三个基本性质

1. **根节点不包含字符**，除根节点外每个节点都只包含一个字符。
2. **从根节点到某一节点，路径上经过的字符连接起来，就是该节点对应的字符串**。
3. **每个节点的所有子节点包含的字符都不相同**。

### 为什么不用哈希表？

| 对比维度 | 哈希表 | Trie |
|---------|--------|------|
| 精确查找 | O(L) | O(L) |
| 前缀查找 | 无法高效支持 | O(L) |
| 字典序遍历 | 无法高效支持 | 支持 |
| 空间（大量公共前缀时） | 较高 | 较低 |

> Trie 的杀手锏是**前缀查找**和**字典序遍历**，这是哈希表做不到的。

## 数据结构设计

### 节点结构

每个节点需要两样东西：
1. **指向子节点的指针数组**（26 个字母 → 26 个子节点指针）
2. **标记是否是单词结尾**（区分"前缀"和"完整单词"）

```cpp
struct Node {
    Node* son[26]{};  // 26 个子节点指针，初始化为 nullptr
    bool end = false; // 标记该节点是否是某个单词的结尾
};
```

### 为什么用数组而不是哈希表？

- 字母只有 26 个，数组大小固定，**访问是 O(1)**
- 数组的内存连续性更好，**缓存友好**
- 代码更简洁，不需要处理哈希冲突

---

## 核心操作详解

### 1. 插入（insert）

**思路**：从根节点出发，沿着单词的每个字符往下走。遇到不存在的子节点就新建，走到最后一个字符时标记 `end = true`。

```
插入 "apple" 的过程：
root
  └── a
      └── p
          └── p
              └── l
                  └── e  ← end = true
```

### 2. 查找（search）

**思路**：从根节点出发，沿着单词的每个字符往下走。如果中途某个字符找不到子节点，返回 false。走到最后一个字符时，检查 `end` 是否为 true。

### 3. 前缀查找（startsWith）

**思路**：和 search 几乎一样，只是走到最后不需要检查 `end`，能走完就说明存在以该前缀开头的单词。

## 完整代码实现

```cpp
class Trie {
private:
    // Trie 节点结构
    struct Node {
        Node* son[26]{};  // 26 个子节点，值初始化（全为 nullptr）
        bool end = false; // 标记是否为单词结尾
    };

    Node* root; // 根节点

    /**
     * @brief 递归销毁以 node 为根的子树，释放内存
     * @param node 当前节点
     */
    void destroy(Node* node) {
        if (node == nullptr) return;
        for (Node* child : node->son) {
            destroy(child);
        }
        delete node;
    }

public:
    /**
     * @brief 构造函数：初始化根节点
     */
    Trie() : root(new Node) {}

    /**
     * @brief 析构函数：递归释放所有节点内存
     */
    ~Trie() {
        destroy(root);
    }

    /**
     * @brief 向 Trie 中插入一个单词
     * @param word 待插入的单词
     */
    void insert(string word) {
        Node* cur = root;
        for (char ch : word) {
            int idx = ch - 'a';
            // 如果子节点不存在，创建新节点
            if (cur->son[idx] == nullptr) {
                cur->son[idx] = new Node;
            }
            // 移动到子节点（必须用 cur->son[idx]，不能用临时指针！）
            cur = cur->son[idx];
        }
        cur->end = true; // 标记单词结束
    }

    /**
     * @brief 查找单词是否存在于 Trie 中
     * @param word 待查找的单词
     * @return 存在返回 true，否则返回 false
     */
    bool search(string word) {
        Node* cur = root;
        for (char ch : word) {
            int idx = ch - 'a';
            if (cur->son[idx] == nullptr) {
                return false; // 中途断了，不存在
            }
            cur = cur->son[idx];
        }
        return cur->end; // 必须是单词结尾才算存在
    }

    /**
     * @brief 查找是否存在以 prefix 为前缀的单词
     * @param prefix 前缀
     * @return 存在返回 true，否则返回 false
     */
    bool startsWith(string prefix) {
        Node* cur = root;
        for (char ch : prefix) {
            int idx = ch - 'a';
            if (cur->son[idx] == nullptr) {
                return false;
            }
            cur = cur->son[idx];
        }
        return true; // 能走完前缀就说明存在
    }
};
```

## 常见错误与陷阱

### ️ 错误 1：insert 中用临时指针导致空指针解引用（最经典的坑）

**错误代码**：
```cpp
void insert(string word) {
    Node* cur = root;
    for (char c : word) {
        c -= 'a';
        Node* son = cur->son[c];  // son 是 cur->son[c] 的"副本"
        if (son == nullptr) {
            cur->son[c] = new Node; // 修改了 cur->son[c]
        }
        cur = son;  // Error: son 仍然是 nullptr！cur 变成了空指针！
    }
    cur->end = true; // 空指针解引用，程序崩溃！
}
```

**为什么错？**

`son` 是一个**局部指针变量**，它保存的是 `cur->son[c]` 的值（地址）。
- 当 `cur->son[c]` 是 `nullptr` 时，`son` 也是 `nullptr`
- 你修改了 `cur->son[c] = new Node`，但 `son` 这个局部变量的值**不会自动更新**
- 所以 `cur = son` 把 `cur` 变成了 `nullptr`，下一次循环 `cur->son[c]` 就是空指针解引用

**正确写法（两种）**：

**写法一：直接用 `cur->son[idx]`（推荐，最清晰）**
```cpp
for (char ch : word) {
    int idx = ch - 'a';
    if (cur->son[idx] == nullptr) {
        cur->son[idx] = new Node;
    }
    cur = cur->son[idx]; // 直接从数组里取最新值
}
```

**写法二：用引用（更优雅）**
```cpp
for (char ch : word) {
    int idx = ch - 'a';
    Node*& child = cur->son[idx]; // child 是 cur->son[idx] 的"别名"
    if (child == nullptr) {
        child = new Node; // 修改 child 就是修改 cur->son[idx]
    }
    cur = child;
}
```

> **一句话记住**：指针是值传递的，要修改原指针就得用引用，或者直接操作原变量。

---

### 错误 2：忘记标记 end = true

插入单词后忘记在最后一个节点设置 `end = true`，会导致 `search` 永远返回 false。

---

### 错误 3：混淆 search 和 startsWith

- `search`：必须走到最后且 `end == true`（是完整单词）
- `startsWith`：只要能走完前缀就行（不一定是完整单词）

很多人写 `search` 时忘了检查 `end`，导致把前缀也当成了完整单词。

---

### 错误 4：内存泄漏

只 `new` 不 `delete`，在 LeetCode 上虽然不会报错（程序结束系统自动回收），但面试中一定要写析构函数，体现良好的内存管理意识。

## 复杂度分析

### 时间复杂度

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| insert | O(L) | L 为单词长度，每个字符处理一次 |
| search | O(L) | 同上 |
| startsWith | O(L) | 同上 |

### 空间复杂度

- **最坏情况**：O(N × L)，其中 N 是单词数，L 是单词平均长度。所有单词都没有公共前缀时，每个字符对应一个节点。
- **实际情况**：有大量公共前缀时，空间远小于 N × L，这正是 Trie 的优势。

## 进阶思考

### 1. 如何支持删除操作？

Trie 的删除比插入复杂，需要考虑：
- 如果单词不存在，直接返回
- 如果单词存在，从叶子节点往上回溯，删除那些**没有其他子节点且不是其他单词结尾**的节点

可以用递归实现，递归返回值表示"当前节点是否可以被删除"。

### 2. 如何统计以某个前缀开头的单词数量？

在节点中增加一个 `count` 字段，插入时沿途每个节点的 `count` 都加 1，查询前缀时直接返回最后一个节点的 `count`。

### 3. 如何实现字典序遍历？

对每个节点，按字母顺序（a→z）递归遍历子节点，遇到 `end == true` 就输出当前单词。这就是 Trie 天然支持字典序的原因。

## 总结

>
> Trie 是一种树形数据结构，专门用于字符串的前缀匹配。它的核心思想是利用公共前缀来节省存储空间和查询时间。
>
> **数据结构设计上**，每个节点包含一个大小为 26 的指针数组（对应 26 个小写字母）和一个布尔标记，标记该节点是否是某个单词的结尾。根节点不存储字符。
>
> **插入操作**：从根节点出发，遍历单词的每个字符。如果对应的子节点不存在就创建，然后移动到子节点。遍历完所有字符后，在最后一个节点标记 `end = true`。
>
> **查找操作**：同样从根出发，沿着字符往下走。如果中途某个字符找不到子节点就返回 false。走到最后时，检查 `end` 标记是否为 true。
>
> **前缀查找**和查找类似，只是走到最后不需要检查 `end`，能走完就说明存在该前缀。
>
> 时间复杂度上，插入、查找、前缀查找都是 O(L)，L 是单词长度。空间复杂度最坏是 O(N×L)，但在有大量公共前缀的情况下会节省很多空间。
>
> 这里有一个容易踩的坑：插入的时候，如果用临时指针保存子节点，新建节点后一定要记得更新临时指针，或者直接用数组下标访问，否则会出现空指针解引用。
